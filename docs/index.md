# vf-wiki

This site is a presentation layer for the repository.

The Git repository is the authoritative source of truth.
All content originates from Markdown files in the repo.

## Start Here

If you are new to this repository, follow this path:

1. **Understand what this repository is**
   - Read: [Repository Overview](repository_overview.md)

2. **Learn how the repository is organized**
   - Read: [Repository Structure](repo_structure.md)

3. **Understand the governing rules**
   - Read the core governance documents:
     - [Lifecycle Model](00_governance/lifecycle_model.md)
     - [Naming & Identification Convention](00_governance/naming_identification_convention.md)
     - [Tailoring & Derived Documents Register](00_governance/tailoring_derived_documents_register.md)

4. **Understand how agents and contributors should behave**
   - Read: [Agent Guide](AGENTS.md)

5. **Follow lifecycle transition processes when needed**
   - Read: [Lifecycle Processes](10_lifecycle/index.md)

6. **Use templates when instantiating project artifacts**
   - Read: [Templates](90_templates/index.md)

After these four steps you should understand:

- how the lifecycle works
- what documents exist
- how they are named
- how the repository should be edited

## Design Principles

- Markdown is the primary artifact format.
- Stable paths, headings, and identifiers matter more than presentation.
- Humans can browse with MkDocs; LLMs can read the repo directly.
- Mermaid diagrams render in the site while staying plain fenced Markdown in source.
- Governance documents define the naming, lifecycle, and traceability model for the rest of the knowledge base.

## Current Scope

The current baseline covers:

- lifecycle structure
- lifecycle transition processes
- reusable document templates
- document naming and identifiers
- MIL-STD-498 tailoring and derived artifacts
